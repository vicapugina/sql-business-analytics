# Аналитические задачи на SQL (Karpov.Courses)

## 📌 Контекст проекта

Проект содержит решения набора аналитических задач, выполненных в рамках курса Karpov.Courses «Симулятор SQL» [citation:7][citation:10]. Работа велась с данными сервиса доставки, имитирующими реальную бизнес-среду [citation:10].

**Главная цель:** не просто написать запросы, а научиться переводить вопросы бизнеса на язык SQL и интерпретировать результаты для принятия управленческих решений [citation:1][citation:7].

## 🛠 Инструменты и технологии

*   **Язык:** SQL (PostgreSQL) [citation:10][citation:12]
*   **BI-инструмент:** Redash (построение дашбордов по результатам запросов) [citation:10]
*   **Обработка данных:** Оконные функции, подзапросы, CTE, агрегаты, JOIN [citation:7][citation:9]

## 📂 Структура репозитория

*   `queries/` — папка с SQL-запросами:
    *   `01_basic_queries.sql` — базовые запросы (SELECT, WHERE, фильтрация)
    *   `02_aggregations.sql` — агрегация и группировка данных
    *   `03_joins_subqueries.sql` — объединение таблиц и подзапросы
    *   `04_window_functions.sql` — оконные функции
*   `insights/` — папка с бизнес-выводами по задачам

## 🧠 Основные типы решённых задач и выводы

**Примеры задач и что они дают для бизнеса:**

| Задача | Используемые SQL-инструменты | Пример бизнес-вывода / инсайта [citation:2] |
| :--- | :--- | :--- |
| **Расчёт ключевых метрик** | Агрегатные функции (`SUM`, `AVG`, `COUNT`), `GROUP BY`, `DATE_TRUNC` | Определение динамики DAU, WAU, удержания (Retention) для оценки роста базы пользователей [citation:10]. |
| **Анализ клиентской базы** | `JOIN`, `COUNT(DISTINCT)`, `ORDER BY` | Выявление ключевых клиентов для программы лояльности и понимание популярности точек продаж [citation:2]. |
| **Кумулятивный анализ** | Оконные функции (`SUM(...) OVER (...)`) | Построение накопительных итогов продаж для отслеживания трендов и прогнозирования выручки [citation:2]. |
| **Сегментация и фильтрация** | `WHERE`, `LIKE`, `CASE`, `HAVING` | Выявление категорий товаров с потенциальными проблемами (например, завышенная цена vs. количество отказов) или поиск товаров с высокой маржинальностью. |
| **Проверка гипотез** | Подзапросы, `WITH` (CTE), `CASE` | Сравнение поведения пользователей из разных групп для поиска точек роста продукта [citation:1]. |
